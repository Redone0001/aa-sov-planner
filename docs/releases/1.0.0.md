# Alliance Auth Sovereignty Planner 1.0.0

First release for **Alliance Auth 5.x**. This release brings together the planner, map, access controls and CSV tools developed up to 0.8.0, with a rewritten installation and feature guide.

## Features

- Projects built from regions and/or individual systems, with ownership snapshots and admin diagnostics.
- Online, Temporary, Planned and Offline upgrade states, with separate current and planned power/workforce budgets and warnings.
- Workforce import/export/transit routes, adjacent-system balancing, and constellation Best ratting optimisation.
- Interactive EVE schematic map, upgrade quick actions, route removal, saved capitals and 5 LY Ansiblex range checks.
- Upgrade inventory copy, upgrade CSV import/export, and workforce-route CSV import/export with validation previews.
- Viewer, Editor and Plan Manager permissions, project visibility restrictions and an optional simplified Viewer view.
- AA theme integration and inline updates without page reloads; verified in Flatly, Darkly and Materia.

## Fresh installation

Requires an existing AA 5.x deployment with its normal database, Redis and Celery services. Activate the **AA virtual environment**, switch to the directory containing your production `manage.py`, and run:

```bash
python -m pip install --upgrade "git+https://github.com/Redone0001/aa-sov-planner.git@v1.0.0"
```

The public HTTPS URL does not require an SSH key. Dependencies include `django-eveonline-sde` 0.2.x and OR-Tools.

In AA's `local.py`, ensure `modeltranslation` is first:

```python
INSTALLED_APPS = ["modeltranslation"] + [
    app for app in INSTALLED_APPS if app != "modeltranslation"
]
```

Add the SDE and planner **once**; omit `eve_sde` if it is already configured:

```python
INSTALLED_APPS += [
    "eve_sde",
    "aasov.apps.SovPlannerConfig",
]
```

Initialise the app:

```bash
python manage.py migrate
python manage.py esde_load_sde
python manage.py collectstatic --noinput
python manage.py check
```

Wait for the SDE load to finish. Skip that load only if a complete, current SDE is already installed. Restart AA's web service and Celery workers using your deployment's normal procedure. The planner registers `/sov-planner/` automatically; Celery handles ownership snapshots.

### Permissions and first project

Assign permissions through your AA groups:

| Role | Permissions |
| --- | --- |
| Viewer | `aasov.view_project` |
| Editor | `aasov.view_project` + `aasov.edit_plan` |
| Plan Manager | `aasov.view_project` + `aasov.edit_plan` + `aasov.manage_plan` |

Administrators creating/configuring projects need staff access and `aasov.add_project` / `aasov.change_project`. These do not automatically grant planner editing permissions. Users must have a **main character set in AA** to open the module.

1. Open **Administration → Sovereignty Planner → Projects → Add**.
2. Name the project and select regions and/or systems.
3. Optionally restrict visibility to selected roles or enable the simplified Viewer view, then save.
4. Open **Sovereignty Planner** in the AA sidebar and choose the project.
5. Add upgrades/routes or use the CSV import tools. Plan Managers can download import templates from the dialogs.

## Upgrading an existing installation

With the existing AA environment activated:

```bash
python -m pip install --upgrade "git+https://github.com/Redone0001/aa-sov-planner.git@v1.0.0"
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
```

Restart AA web services and Celery workers and refresh the browser. Existing plans are preserved. There are no new migrations compared with 0.8.0; installations upgrading from earlier versions must apply any outstanding migrations.

## Downloads and validation

The release includes a Python wheel and source distribution, plus SHA-256 checksums. The Git-tag installation command above is the recommended setup path.

- **160 automated tests passed** on Python 3.12, AA 5.3.1, Django 5.2.17 and SDE 0.2.0.
- Lint, Django system checks and migration checks passed; wheel and source distribution built successfully.
- Browser workflows have been checked in Flatly, Darkly and Materia. Production database concurrency still needs deployment-specific verification on MySQL/MariaDB.

The planner uses SDE potential and ownership snapshots, not live upgrade/fuel state, and makes no in-game changes. Upgrade CSV imports set all imported entries to Planned, including entries exported with another status.

See the [README](https://github.com/Redone0001/aa-sov-planner/blob/v1.0.0/README.md) for features, access rules, scheduled SDE updates and ownership maintenance, and the [browser validation record](https://github.com/Redone0001/aa-sov-planner/blob/v1.0.0/docs/theme-validation.md) for theme checks.
