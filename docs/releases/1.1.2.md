# Alliance Auth Sovereignty Planner 1.1.2

Version 1.1.2 accepts `django-eveonline-sde>=0.2.0,<3`, retaining support for 0.2.0 and adding support for 2.0.0. The planner uses the same SDE models and queries across these versions. The runtime requires Alliance Auth 5.x and Django 5.2.x.

## Changes

- Broaden the SDE dependency range and declare the Django 5.2 requirement explicitly.
- Add loader regression tests for resource aggregation, upgrade costs and fuel, gate routes, saved references and protected obsolete upgrades. REST records are exercised on SDE 2.0 alongside ZIP records.
- Document SDE 2.0 migrations, the initial reload, hourly update checks and rollback requirements.
- Include the exploration halos and saved logistics links introduced since the 1.0.0 release.

SDE 0.2.0 remains usable with loaded data and initial imports. Its upstream updater has an existing defect when changed resource rows are sent to Django's `bulk_update`: it includes primary-key fields, which Django rejects. The regression suite records this expected failure; SDE 1.0.0 and 2.0.0 pass the reload checks. This release does not patch the dependency's updater.

## Installation and upgrade

With your existing AA virtual environment activated:

```bash
python -m pip install --upgrade "git+https://github.com/Redone0001/aa-sov-planner.git@v1.1.2"
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
```

The dependency range permits both SDE 0.2.0 and 2.0.0. Append `"django-eveonline-sde==0.2.0"` to the install command to retain 0.2.0 explicitly, or `"django-eveonline-sde==2.0.0"` to select the new version. Every other installed plugin must support the selected SDE version too; this release does not resolve other plugins' constraints.

There are no new planner migrations compared with 1.1.0/1.1.1. Upgrades from 1.0.0 apply `0008_logisticslink`. Restart AA web services and Celery workers after completing the upgrade.

## Moving from SDE 0.2.0 to 2.0.0

Back up the database, configuration and package versions and rehearse on a production database clone. Pause scheduled SDE updates, install the compatible package set, review `python manage.py migrate --plan`, then apply migrations. SDE migrations `0037`–`0040` add certificate/mastery tables, deduplicate relation rows, add unique constraints and track imports and REST releases.

Review `python manage.py esde_load_sde --plan`, then run `python manage.py esde_load_sde --full`. SDE 2.0 defaults to CCP's REST API and reloads all models on the first REST load. `ESDE_SOURCE = "zip"` is the fallback within SDE 2.0. Inspect section counts, import logs and protected-deletion errors, verify existing plans, then run Django's system checks and `python -m pip check` before resuming normal services. If SDE 2.0 has already completed migrations and loading, the planner upgrade alone does not require another reload.

Use `crontab(minute="30")` for the existing `eve_sde.tasks.check_for_sde_updates` schedule, following upstream's hourly recommendation. Restart Celery Beat after changing its configuration.

To revert the SDE migration or reload, restore the matching database backup and previous package/configuration set together. Reversing migrations alone cannot restore duplicate rows removed by migration `0038`.

## Validation

The full suite was run on Python 3.12.14, Alliance Auth 5.3.1 and Django 5.2.17:

| SDE version | Result |
| --- | --- |
| 0.2.0 | 169 passed, 4 skipped, 1 expected failure for the upstream updater defect described above |
| 1.0.0 | 171 passed, 3 skipped because REST imports are unavailable |
| 2.0.0 | 174 passed |

Ruff, Django system checks and planner migration checks passed. The wheel and source distribution were built and inspected. Tests use SQLite and synthetic data; the production database engine and a full live SDE import still require staging validation. The local test environments lack AA's native MySQL driver, so their `pip check` reports that missing driver; the built planner's SDE dependency conflict is resolved.

See the [README](https://github.com/Redone0001/aa-sov-planner/blob/v1.1.2/README.md) for configuration and workflows, and the [upstream SDE 2.0.0 release](https://github.com/Solar-Helix-Independent-Transport/django-eveonline-sde/releases/tag/2.0.0) for its loader changes.
